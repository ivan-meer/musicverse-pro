# Requirements Document: Bot Flow Improvements

## Introduction

Данная спецификация описывает улучшения пользовательского опыта взаимодействия с Telegram ботом MusicVerse Pro. Улучшения включают:
- Приветственное сообщение с deep link на профиль в Mini App и закрепление в чате
- Многоуровневую систему меню с автозаменой/автоудалением для избежания спама
- Систему уведомлений о прогрессе с автоудалением временных сообщений

Эти улучшения направлены на создание чистого, удобного интерфейса бота без захламления чата пользователя.

## Glossary

- **Bot**: Telegram бот MusicVerse Pro
- **System**: Комплексная система бота и Mini App
- **User**: Пользователь Telegram, взаимодействующий с ботом
- **Deep Link**: Специальная ссылка для открытия конкретной страницы в Mini App
- **Pinned Message**: Закрепленное сообщение в чате, видимое всегда сверху
- **Inline Keyboard**: Интерактивные кнопки под сообщением бота
- **Message Edit**: Редактирование существующего сообщения вместо отправки нового
- **Auto-delete**: Автоматическое удаление сообщения через определенное время
- **Progress Notification**: Уведомление о ходе выполнения длительной операции
- **Menu State**: Текущее состояние многоуровневого меню
- **Callback Query**: Событие нажатия на inline кнопку
- **Message ID**: Уникальный идентификатор сообщения в чате
- **Chat Session**: Сессия взаимодействия пользователя с ботом

## Requirements

### Requirement 1

**User Story:** Как пользователь, я хочу видеть приветственное сообщение с быстрым доступом к моему профилю в Mini App, закрепленное в чате, чтобы всегда иметь доступ к основным функциям.

#### Acceptance Criteria

1. WHEN пользователь отправляет команду /start THEN THE System SHALL отправить приветственное сообщение с inline кнопкой deep link на страницу профиля
2. WHEN приветственное сообщение отправлено THEN THE System SHALL автоматически закрепить это сообщение в чате
3. WHEN пользователь нажимает на deep link кнопку THEN THE System SHALL открыть Mini App на странице профиля пользователя
4. WHEN пользователь повторно отправляет /start THEN THE System SHALL обновить существующее закрепленное сообщение вместо создания нового
5. WHEN закрепление сообщения невозможно из-за прав доступа THEN THE System SHALL продолжить работу без ошибки

### Requirement 2

**User Story:** Как пользователь, я хочу взаимодействовать с многоуровневым меню через одно сообщение, которое обновляется, чтобы мой чат оставался чистым без спама.

#### Acceptance Criteria

1. WHEN пользователь открывает главное меню THEN THE System SHALL отправить сообщение с inline кнопками первого уровня
2. WHEN пользователь нажимает кнопку подменю THEN THE System SHALL отредактировать текущее сообщение, заменив содержимое и кнопки на следующий уровень
3. WHEN пользователь нажимает кнопку "Назад" THEN THE System SHALL отредактировать сообщение, вернув предыдущий уровень меню
4. WHEN пользователь выбирает действие в меню THEN THE System SHALL выполнить действие и обновить сообщение с результатом
5. WHEN происходит ошибка при редактировании сообщения THEN THE System SHALL отправить новое сообщение и удалить старое

### Requirement 3

**User Story:** Как пользователь, я хочу видеть уведомления о прогрессе длительных операций, которые автоматически удаляются после завершения, чтобы не захламлять чат.

#### Acceptance Criteria

1. WHEN начинается длительная операция THEN THE System SHALL отправить сообщение с индикатором прогресса
2. WHEN операция выполняется THEN THE System SHALL обновлять сообщение с текущим статусом прогресса
3. WHEN операция завершается успешно THEN THE System SHALL обновить сообщение с результатом и автоматически удалить его через 5 секунд
4. WHEN операция завершается с ошибкой THEN THE System SHALL обновить сообщение с описанием ошибки и автоматически удалить его через 10 секунд
5. WHEN пользователь взаимодействует с результатом до автоудаления THEN THE System SHALL отменить автоудаление и сохранить сообщение

### Requirement 4

**User Story:** Как разработчик, я хочу иметь систему управления состоянием меню, чтобы корректно обрабатывать навигацию по многоуровневым меню.

#### Acceptance Criteria

1. WHEN пользователь открывает меню THEN THE System SHALL сохранить состояние меню в памяти с message_id и текущим уровнем
2. WHEN пользователь переходит на новый уровень меню THEN THE System SHALL обновить состояние с новым уровнем и историей навигации
3. WHEN пользователь нажимает "Назад" THEN THE System SHALL восстановить предыдущее состояние из истории навигации
4. WHEN сессия пользователя истекает THEN THE System SHALL очистить состояние меню для этого пользователя
5. WHEN пользователь открывает новое меню THEN THE System SHALL заменить старое состояние новым

### Requirement 5

**User Story:** Как пользователь, я хочу получать уведомления о важных событиях (новые рекомендации, обновления плейлистов), которые не захламляют чат.

#### Acceptance Criteria

1. WHEN происходит важное событие THEN THE System SHALL отправить уведомление с кратким описанием и inline кнопками действий
2. WHEN пользователь не взаимодействует с уведомлением в течение 30 секунд THEN THE System SHALL автоматически удалить кнопки, оставив только текст
3. WHEN пользователь нажимает на действие в уведомлении THEN THE System SHALL выполнить действие и обновить уведомление с результатом
4. WHEN уведомление обработано THEN THE System SHALL автоматически удалить его через 5 секунд
5. WHEN пользователь отключил уведомления в настройках THEN THE System SHALL не отправлять автоудаляемые уведомления

### Requirement 6

**User Story:** Как пользователь, я хочу видеть структурированное главное меню с категориями функций, чтобы легко находить нужные действия.

#### Acceptance Criteria

1. WHEN пользователь открывает главное меню THEN THE System SHALL отобразить категории: Музыка, Плейлисты, Избранное, Настройки
2. WHEN пользователь выбирает категорию "Музыка" THEN THE System SHALL показать подменю с опциями: Рекомендации, Поиск, Жанры, Новинки
3. WHEN пользователь выбирает категорию "Плейлисты" THEN THE System SHALL показать подменю с опциями: Мои плейлисты, Создать новый, Популярные
4. WHEN пользователь выбирает категорию "Избранное" THEN THE System SHALL показать подменю с опциями: Все треки, По жанрам, Недавно добавленные
5. WHEN пользователь выбирает категорию "Настройки" THEN THE System SHALL показать подменю с опциями: Уведомления, Язык, Профиль, О приложении

### Requirement 7

**User Story:** Как разработчик, я хочу иметь систему очереди сообщений для автоудаления, чтобы корректно управлять временными сообщениями.

#### Acceptance Criteria

1. WHEN создается временное сообщение THEN THE System SHALL добавить его в очередь автоудаления с указанным таймаутом
2. WHEN таймаут истекает THEN THE System SHALL удалить сообщение из чата и из очереди
3. WHEN сообщение удаляется вручную до истечения таймаута THEN THE System SHALL удалить его из очереди автоудаления
4. WHEN бот перезапускается THEN THE System SHALL восстановить очередь автоудаления из базы данных
5. WHEN удаление сообщения невозможно THEN THE System SHALL логировать ошибку и удалить запись из очереди

### Requirement 8

**User Story:** Как пользователь, я хочу видеть breadcrumbs (хлебные крошки) в меню, чтобы понимать, где я нахожусь в структуре меню.

#### Acceptance Criteria

1. WHEN пользователь находится на втором уровне меню THEN THE System SHALL отображать путь навигации в заголовке сообщения
2. WHEN пользователь переходит глубже в меню THEN THE System SHALL обновлять breadcrumbs с полным путем
3. WHEN пользователь нажимает на элемент breadcrumbs THEN THE System SHALL перейти на соответствующий уровень меню
4. WHEN пользователь находится на главном уровне THEN THE System SHALL не отображать breadcrumbs
5. WHEN путь навигации слишком длинный THEN THE System SHALL сокращать промежуточные уровни с использованием "..."

### Requirement 9

**User Story:** Как пользователь, я хочу получать визуальную обратную связь при нажатии на кнопки меню, чтобы понимать, что действие обрабатывается.

#### Acceptance Criteria

1. WHEN пользователь нажимает на inline кнопку THEN THE System SHALL немедленно отправить callback answer с текстом "Загрузка..."
2. WHEN действие выполняется быстро (< 1 секунды) THEN THE System SHALL показать callback answer с результатом
3. WHEN действие выполняется долго (> 1 секунды) THEN THE System SHALL обновить сообщение с индикатором загрузки
4. WHEN действие завершается THEN THE System SHALL обновить сообщение с результатом
5. WHEN происходит ошибка THEN THE System SHALL показать callback answer с описанием ошибки

### Requirement 10

**User Story:** Как разработчик, я хочу иметь конфигурируемые таймауты для автоудаления разных типов сообщений, чтобы оптимизировать пользовательский опыт.

#### Acceptance Criteria

1. WHEN система инициализируется THEN THE System SHALL загрузить конфигурацию таймаутов из переменных окружения или использовать значения по умолчанию
2. WHEN создается сообщение о прогрессе THEN THE System SHALL использовать таймаут PROGRESS_MESSAGE_TIMEOUT (по умолчанию 5 секунд)
3. WHEN создается сообщение об ошибке THEN THE System SHALL использовать таймаут ERROR_MESSAGE_TIMEOUT (по умолчанию 10 секунд)
4. WHEN создается уведомление THEN THE System SHALL использовать таймаут NOTIFICATION_TIMEOUT (по умолчанию 30 секунд)
5. WHEN создается временное информационное сообщение THEN THE System SHALL использовать таймаут INFO_MESSAGE_TIMEOUT (по умолчанию 15 секунд)
