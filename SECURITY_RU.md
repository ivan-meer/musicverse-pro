# Политика безопасности

## Реализованные меры безопасности

### 1. Аутентификация и авторизация

#### Верификация данных Telegram Web App
- ✅ Реализована верификация подписи HMAC-SHA256
- ✅ Проверка срока действия init data (TTL 1 час)
- ✅ Извлечение и валидация данных пользователя
- ✅ Правильная обработка ошибок аутентификации

**Реализация**: `bot/utils/auth.js`

**Как это работает**:
1. Парсинг init data от Telegram Web App
2. Извлечение хэша и создание data-check-string
3. Вычисление HMAC-SHA256 используя токен бота
4. Сравнение вычисленного хэша с предоставленным
5. Проверка, что auth_date в пределах 1 часа

### 2. Ограничение запросов

#### Endpoint аутентификации
- ✅ **5 запросов в минуту** на IP адрес
- ✅ Применяется к endpoint `/api/auth/verify`
- ✅ Возвращает статус 429 при превышении лимита

#### Общие API Endpoints
- ✅ **100 запросов в минуту** на IP адрес
- ✅ Применяется ко всем endpoints `/api/*`
- ✅ Отслеживание в памяти (подходит для одного экземпляра)

**Реализация**: `bot/middleware/rateLimiter.js`

**Для продакшена**: Рассмотрите ограничение запросов на основе Redis для мульти-экземплярных развертываний.

### 3. Конфигурация CORS

- ✅ Ограничено только доменами Telegram
- ✅ Разрешенные origins:
  - `https://web.telegram.org`
  - `https://telegram.org`
- ✅ Credentials включены для аутентифицированных запросов

**Реализация**: `bot/webapp.js` (строки 9-12)

### 4. Валидация входных данных

- ✅ Валидация обязательных полей
- ✅ Правильные сообщения об ошибках без утечки чувствительной информации
- ✅ Проверка типов для данных пользователя

### 5. Переменные окружения

- ✅ Чувствительные данные хранятся в переменных окружения
- ✅ Предоставлен `.env.example` без секретов
- ✅ `.gitignore` исключает файл `.env`

**Критические переменные**:
- `TELEGRAM_BOT_TOKEN` - Аутентификация бота
- `JWT_SECRET` - Подпись JWT (если реализовано)
- `DATABASE_URL` - Учетные данные базы данных
- `ENCRYPTION_KEY` - Шифрование данных

### 6. Требование HTTPS

- ✅ Telegram требует HTTPS для Mini Apps
- ✅ Документация включает руководство по настройке HTTPS
- ✅ Предоставлены инструкции по SSL сертификату

## Лучшие практики безопасности

### Для разработки

1. **Никогда не коммитьте секреты**
   - Используйте `.env` для локальной разработки
   - Держите `.env` вне контроля версий
   - Используйте разные токены для dev/prod

2. **Используйте конфигурации для конкретных окружений**
   - Разработка: `NODE_ENV=development`
   - Продакшн: `NODE_ENV=production`

3. **Регулярные обновления**
   - Держите зависимости обновленными
   - Мониторьте уведомления о безопасности
   - Регулярно запускайте `npm audit`

### Для продакшена

1. **Используйте правильное ограничение запросов**
   - Реализуйте ограничение запросов на основе Redis
   - Установите соответствующие лимиты для каждого endpoint
   - Мониторьте паттерны злоупотреблений

2. **Включите логирование и мониторинг**
   - Логируйте попытки аутентификации
   - Мониторьте неудачные запросы
   - Настройте оповещения о подозрительной активности

3. **Безопасность базы данных**
   - Используйте параметризованные запросы
   - Реализуйте connection pooling
   - Включите SSL для подключений к базе данных
   - Регулярные резервные копии

4. **Дополнительные заголовки безопасности**
   ```javascript
   app.use(helmet());
   ```

5. **Безопасность API**
   - Валидируйте все входные данные
   - Санитизируйте пользовательские данные
   - Реализуйте лимиты размера запросов
   - Используйте защиту от CSRF

## Известные ограничения

### Текущая реализация

1. **Ограничение запросов в памяти**
   - ⚠️ Не подходит для мульти-экземплярных развертываний
   - ⚠️ Данные теряются при перезапуске
   - ✅ Приемлемо для одного экземпляра или разработки

2. **Нет постоянных сессий**
   - Каждый запрос без состояния
   - Используются init data Telegram Web App для аутентификации

3. **Нет шифрования базы данных**
   - Реализуйте шифрование в покое для чувствительных данных
   - Используйте зашифрованные соединения (SSL/TLS)
